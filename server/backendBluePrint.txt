📁 Proposed Monolith Server Folder Structure

Here is how we can structure the backend/ directory to keep it simple yet perfectly prepared for the future:
text
backend/
├── src/
│   ├── config/             # Database connection (db.ts) and environment variables
│   ├── models/             # Mongoose schemas & TypeScript type definitions
│   ├── controllers/        # Request handlers (business logic matching your simulated actions)
│   ├── routes/             # Express API endpoints (/api/auth, /api/branches, /api/queue)
│   ├── middleware/         # Auth guards, role validation, and error handlers
│   ├── index.ts            # Server entry point (Express app initialization + Socket.io setup)
│   └── types/              # Global express or request type overrides
├── package.json
└── tsconfig.json
Use code with caution.

⚙️ Mapping Simulated Front-End Actions to Backend Routes

To replace your AppContext.tsx memory engine smoothly, your controllers will directly process these lightweight API endpoints:
• Authentication & Entry Gateway:
	• POST /api/auth/register-simulated \(\rightarrow \) Evaluates the presence of the inviteCode string. Automatically flags the user model as an owner or maps them to a specific branch as a worker.
• Branch Infrastructure:
	• POST /api/branches \(\rightarrow \) Generates the branch slug and the unique auto-generated employee key string (AMHL-XYZ-12).
	• GET /api/branches \(\rightarrow \) Returns clusters based on the owner's ID or limits a worker to their assigned node.
• Live Queue Pipeline (The Priority Engine):
	• POST /api/queue/join \(\rightarrow \) Triggered by the customer web form or manual entry. Calculates the current capacity length \(+1\) and appends a 3-digit rolling ticket string.
	• POST /api/queue/:ticketId/skip \(\rightarrow \) Pulls the document out of its current position array index and pushes it to the back of the queue.
	• POST /api/queue/:ticketId/complete \(\rightarrow \) Deletes or archives the ticket from the active lane collection and creates a document entry inside the CompletionLogs collection.
	• DELETE /api/queue/:ticketId/ghost \(\rightarrow \) Instantly purges an absent client document cleanly without creating a completion footprint.

📡 The Secret Sauce: Real-Time Synchronization

Since we are aiming for a flawless operational experience where worker desks and customer mobile HUD screens stay updated instantly without manual refreshing, we will bake Socket.io directly into this monolith. Whenever a queue route (skip, complete, join) fires a database mutation, the controller will broadcast the fresh state down the websocket pipeline.
